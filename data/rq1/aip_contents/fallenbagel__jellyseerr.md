## <mark>AI Assistance Notice</mark>

> [!IMPORTANT]
>
> <mark>Automated AI-generated contributions without human review are not allowed and will be rejected.</mark>
> This is an open-source project maintained by volunteers.
> <mark>We do not have the resources to review pull requests that could have been avoided with proper human oversight.</mark>
> <mark>While we have no issue with contributors using AI tools as an aid, it is your responsibility as a contributor to ensure that all submissions are carefully reviewed and meet our quality standards.</mark>
>
> <mark>**We expect AI-assisted development, not AI-driven development.**</mark>
> <mark>Use AI as a tool to help you write code. Do not let an AI agent</mark>
> autonomously generate an entire contribution and submit it on your behalf.
> <mark>We have been increasingly receiving low-effort, fully AI-generated PRs</mark>
> and will not tolerate them. Contributors who repeatedly submit unreviewed
> AI output may result in a ban.
>
> <mark>**Submissions that appear to be unreviewed AI output will be considered low-effort and may result in a ban.** Signs of unreviewed AI output include but are not limited to:</mark>
>
> - Blank or template-default PR descriptions
> <mark>- AI-generated PR descriptions that replace our template with their own structure (e.g., "Summary / What changed / Root cause / Test plan" instead of following the PR template; this is the default output format of tools like Claude Code and is an immediate indicator that the PR was not reviewed by a human)</mark>
> - Unchecked checklists or missing checklist entirely
> - Failing CI checks that would have been caught by running `pnpm build`
> - Code that does not match the described changes
> - Inability to answer questions about the submitted code
>
> **Read and follow the [Contributing Guide](CONTRIBUTING.md) before submitting.**
> <mark>If your AI tool generates its own PR description format, it is your</mark>
> responsibility to rewrite it to follow our template before submitting.
> An incomplete PR template tells maintainers that insufficient review has
> been performed on the submission, regardless of the actual code quality.
> We may close such PRs without review.
>
> <mark>If you are using **any kind of AI assistance** to contribute to Seerr, it must be disclosed in the pull request.</mark>

### Disclosure Requirements

<mark>If you are using any kind of AI assistance while contributing to Seerr,</mark>
**this must be disclosed in the pull request description**, along with
<mark>the extent to which AI assistance was used (e.g., docs only vs. code generation).</mark>
<mark>If PR responses (comments, review replies) are being generated by AI,</mark>
disclose that as well.

As a small exception, trivial tab-completion doesn't need to be disclosed,
so long as it is limited to single keywords or short phrases.

Example disclosures:

> <mark>**AI Disclosure:** This PR was written primarily by Claude Code.</mark>
> <mark>**AI Disclosure:** I consulted ChatGPT to understand the codebase but the solution</mark>
> was fully authored manually by myself.
> <mark>**AI Disclosure:** None.</mark>

<mark>When using AI assistance, we expect contributors to:</mark>

- **Understand the code** that is produced and be able to answer
  questions about it.
- <mark>**Follow the contributing guide**. AI tools do not excuse you from</mark>
  filling out the PR template, testing section, and checklist.
- **Run the build and tests** before submitting.

<mark>Failure to disclose AI assistance is first and foremost disrespectful to the</mark>
human maintainers on the other end of the pull request, but it also makes it
difficult to determine how much scrutiny to apply to the contribution.

<mark>In a perfect world, AI assistance would produce equal or higher quality</mark>
work than any human. That is not the world we live in today, and in most cases
<mark>it is generating slop.</mark>

<mark>When using AI assistance, we expect contributors to understand the code</mark>
that is produced and be able to answer critical questions about it. It
is not a maintainer's job to review a PR so broken that it requires
significant rework to be acceptable.

<mark>Please be respectful to maintainers and disclose AI assistance.</mark>

### <mark>Expectations for AI-Assisted Contributions</mark>

1. **PR descriptions and all comments must be your own words.** Do not paste
<mark>LLM output as your PR description, review response, or issue comment.</mark>
   We want *your* understanding and explanation of the changes, not a
<mark>machine-generated summary. An exception is made for LLM-assisted</mark>
   translation, however, note it explicitly if used.

2. **Contributions must be concise and focused.** A PR that claims to fix one thing
   but touches a bunch of unrelated code will be rejected. This is a
   common side effect of broad AI prompts and makes review unnecessarily
   difficult.

3. **You must be able to handle review feedback yourself.** If you cannot discuss or
   implement requested changes without round-tripping reviewer comments
   through an AI, that tells us you don't understand the code you
   submitted. We will close the PR.

4. <mark>**Don't commit non-project files.** Editor configs, AI tool</mark>
   directories, and other local tooling files do not belong in the
   repository. Keep your commits clean.

5. **Changes must be tested.** Build the project, run the tests, and
   manually verify the functionality you modified. Don't just assume
   CI will catch everything.

6. **Final discretion lies with the reviewers.** If a PR cannot be
   reasonably reviewed for any reason due to over-complexity, size, or poor
<mark>structure, it will be rejected. This applies equally to AI-assisted</mark>
<mark>and non-AI-assisted contributions.</mark>
