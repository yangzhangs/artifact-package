## Pull Request Process

1. **Open an issue first.** Every PR must reference an issue. If none exists, open one to discuss the change with maintainers before writing code. PRs without a linked issue may be closed.
2. **Fill out the PR template completely.** When you open a PR, the description will be pre-filled with a template. Fill out every section — PRs with empty or placeholder sections will not be reviewed.
3. **Write your PR description yourself.** The description must be in your own words and accurately reflect what you changed and why. Copy-pasted AI-generated summaries will be rejected.
4. Please do not include any build artifacts unless absolutely necessary.
5. Update the README.md with details of changes to the interface, this includes new environment variables, exposed ports, useful file locations and container parameters.
6. You're free to choose what you want to work on - there will always be existing issues and we welcome all feature requests.
7. If you choose to work on an issue, please check on the thread if there has been any activity - if someone's working on something, check with them and see if they'd like help, or if they're still working on it.
8. If you choose to add a new feature, please open an issue with a title that starts with [FR] and we can have a quick discussion to see viability!
9. When you're ready, open a pull request, add a detailed description of what you've done, and we'll be in touch! Do not hesitate to update it if you find you missed/wanted to add something.

## AI-Assisted Contributions

We welcome contributions where AI tools (Copilot, ChatGPT, Claude, etc.) were used to assist development. However, **AI-assisted is not the same as AI-authored**.

**What we expect:**
- You understand every line of code you submit and can explain any part of it if asked
- Your PR description is written by you, not generated by AI
- You have reviewed all AI-generated code for correctness, security issues, and adherence to project patterns
- You disclose AI usage via the checkbox in the PR template

**What will get your PR closed:**
- Submitting bulk AI-generated code without review or understanding
- AI-generated PR descriptions (these are obvious and easy to spot)
- Inability to explain your own changes when asked
- PRs that introduce code patterns inconsistent with the rest of the project, suggesting a lack of familiarity with the codebase
