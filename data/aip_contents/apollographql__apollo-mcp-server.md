### PR quality expectations

Every pull request should reflect a genuine understanding of the problem and the codebase. We will close PRs that:

* Were submitted without a prior issue discussion or maintainer sign-off (exception: small bug fixes under ~20 lines with tests, as described below).
* <mark>Contain low-quality or AI-generated code that hasn't been reviewed, tested, or adapted to the project's conventions by the author.</mark>
* Make broad, speculative changes unrelated to a specific agreed-upon issue.

<mark>We're not against using AI tools to assist your work, but you are responsible for every line of code you submit. If you can't explain your changes, debug failures, or respond to review feedback, the PR isn't ready. **Authorship means accountability.**</mark>
